# Domain docs

This project uses a single domain context.

## Before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read relevant architectural decision records in `docs/adr/`.
- If these documents are absent, continue silently.
  Domain modeling creates them when terms and decisions are resolved.

## Vocabulary

Use the glossary's terms in specifications, tickets, code and tests.
When a needed concept is missing, identify the gap for domain modeling.

## Architectural decisions

When a proposal conflicts with an existing ADR, explicitly identify
the conflicting ADR and explain why the decision should be reopened.
